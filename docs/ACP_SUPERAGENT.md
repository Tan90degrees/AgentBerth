# ACP Agent 与 Superagent

适用 AgentBerth 0.20 / 后台 API 53。ACP 使用稳定 v1 的逐行 JSON-RPC stdio 协议，不捆绑模型或 Agent 运行时。已有 CLI / TUI 接入继续可用。

## 配置已有 ACP Agent

在「插件中心 → Agent 接入 → 新增 ACP Agent」填写名称、启动程序与 JSON 参数数组。OpenCode 示例：

```text
名称：OpenCode ACP
启动程序：opencode
启动参数：["acp"]
```

使用本机已安装、已登录的 OpenCode。Windows 支持 PATH 中的 `.exe`、`.cmd`、`.bat` 和 `.ps1` 启动器；也可「选择文件」直接选择程序或脚本。含空格的完整路径保持为一个文件名，不需要加引号；粘贴时已有的成对外层引号也可以处理。程序与参数分开填写，不把整段 shell 命令放入程序字段。环境变量默认继承本机；高级配置仅用于明确覆盖，保存在本机配置中。不要把令牌写入可分享的插件包。

脚本配置示例：

| 类型 | 启动程序 | 启动参数（JSON 数组） |
| --- | --- | --- |
| PowerShell | `C:\Program Files\My Agent\start-acp.ps1` | `["acp"]`，或脚本不需要参数时 `[]` |
| 批处理 | `C:\Program Files\My Agent\start-acp.cmd` | `[]` |
| Python | `python` 或解释器完整路径 | `["C:\\Agent Scripts\\start_acp.py"]` |
| JavaScript | `node` 或解释器完整路径 | `["C:\\Agent Scripts\\start-acp.mjs"]` |

`.ps1` 通过无 profile 的 PowerShell 启动，仅对此子进程使用执行策略参数，不修改系统执行策略。其他脚本使用其真实解释器；Unix 下也可直接运行有执行权限且带 shebang 的脚本。脚本的 stdout 必须只写 ACP JSON-RPC，日志写 stderr。脚本内部调用其他程序也须保留完整路径与参数边界。

遇到 `spawn … ENOENT` 时核对程序/解释器、脚本内部调用的程序和项目目录是否存在；路径不要只填写到含空格文件名的前一部分。「测试连接」使用同一启动链，先确认能力协商成功再创建会话。

Windows 下不写扩展名时优先查找 `.exe/.com/.cmd/.bat/.ps1`。npm 同时安装的无扩展名 Unix shim 不会再被误当作 Windows 可执行文件；仅有这类脚本时会提示选择解释器。

「测试连接」只做 initialize 能力协商，不创建会话、不运行任务。Claude Code、Codex 等需填写各自真正提供 ACP 的适配器程序；普通 `claude` 或 `codex` 的交互命令不能直接视为 ACP 服务。不同适配器的安装、登录和授权方式由其维护者提供，工作台不静默替换适配器。

普通 ACP 对话：回到左侧项目，右键新建会话并选择该 Agent。主区变为对话：Enter 发送，Shift+Enter 换行；支持流式回复、计划、工具调用和手动授权。项目/会话的创建、重命名、删除、连接与断开仍在左侧。停止当前轮次与断开 Agent 是两种操作。

模式、模型选项、登录入口只在 Agent 实际声明后显示。Agent 未声明能力时不会伪造对应入口。项目 Skills 目录可在接入高级设置中填写；插件方式可同时注册 ACP 和 Skills：

```js
exports.apply = ctx => {
  ctx.berth.agent({
    id: 'my-acp',
    definition: {
      name: 'My ACP Agent', command: 'my-agent',
      acp: { executable: 'my-agent', args: ['acp'], env: {} },
      skills: { project: '.my-agent/skills' }
    }
  });
};
```

仅声明 Agent 真正读取的 Skills 目录，工作台不更改其私有配置。

### 历史、恢复与权限

ACP 对话记录由工作台保存，不解析 CLI 私有 JSONL，也不读取终端画面充当回答。初次加载最近 100 个事件，可以加载更早的消息。每会话保留最近 5000 个事件，单个文本事件拆分为最多 8192 字；这是有界日志，不承诺无限历史归档。

重新连接时，Agent 声明 `loadSession` 才恢复原生会话；未声明时保留本机记录、明确提示并新建原生会话。配置或工作区变化也会明确建立新绑定。未知结果不自动重发旧消息，同一 `requestId` 不重复执行。托盘退出后恢复只重建连接，不自动继续被中断的任务。

Agent 可以调用项目范围内的客户端文本文件读写与命令工具；文件限制 1 MiB，路径包含符号链接校验。命令输出最多 1 MiB，截断有显式标记，等待退出后读取已排空的输出。授权请求必须由用户选择，工作台不会默认批准。但 ACP Agent 本身是当前用户启动的本机程序，原生工具权限由 Agent 自身决定，这不是进程沙箱。

协议参考：[ACP v1](https://agentclientprotocol.com/protocol/v1/initialization)、[OpenCode ACP](https://opencode.ai/docs/acp)。

## Superagent 的使用方式

日常处理入口：

1. 来源发来新请求后，Superagent 的「待批准」显示数量，侧栏也提示待处理任务。收件箱直接展示请求内容、来源、发起人、处理项目与执行 Agent；选择 **批准并开始** 或 **拒绝**。Agent 已不可用时，可在详情更改本条任务的 Agent 后批准；管道任务的项目固定，需切换项目时在目标管道新建任务。
2. 执行期间查看进度、回答问题、排队补充要求；完成后验收。任务信息和内部会话历史折叠在次要区域。
3. 需要通知发起人时，展开 **发送回复到原渠道（可选）**，核对接收渠道、人员和正文，确认发送。它会通过来源插件向这条请求所在的原对话发送文字。**批准任务、确认完成均不会自动发送渠道消息。** 仅接收型来源不显示发送控件，并说明不支持回复。

来源管道按名称独立管理项目、ACP Agent、模型和固定 Git Worktree。一个管道可接收多个信息源，每个来源独立选择会话范围；同一来源可分发给多个管道，匹配消息在每条管道各生成一项任务。接收记录显示各管道成功任务与失败原因，只重试失败分发。事件首次接收时固定订阅管道，后来新增的订阅不会补发旧事件。任务可按管道筛选、搜索和批量操作。开发文档统一位于所属插件设置。

每个管道首次运行时创建自己的 Git Worktree，协调和执行会话均使用此目录，同管道任务串行；回答问题、授权、验收和中断待确认会保留工作区，完成或取消后才处理下一项。不同管道可并行。已有工作区的管道不能更换项目，删除任务或管道保留文件，不自动提交、合并或清理。旧任务保留原工作目录。非 Git 项目可在管道“工作区”扫描并确认建立隔离副本，支持差异预览、选择应用、冲突检查及导出；不会回退到共享目录。

任务列表支持按管道筛选、搜索和分页；管道卡片的「查看任务」直接打开该管道。新建任务可选择已有管道，或建立独立任务。任务右上角「更多任务操作 → 删除任务」删除本地任务、内部会话和本地对话记录；运行中需要明确确认取消并删除。保留 Git Worktree 中的文件、普通会话以及原渠道已发送的消息。后台保留来源事件的去重标识，旧事件重发不会重新创建已删除任务。回复发送中需要等待结果后才能删除。

在侧栏打开 Superagent，选择项目、ACP 协调者和 ACP 执行者，填写任务与验收要求。可以选择同一种 Agent，但每个任务的协调/执行都使用独立会话。Git 项目默认创建独立 Worktree；非 Git 项目取消该选项。

流程是：确定性准入 → 协调者决策 → 独立执行者 → 人工确认结果。协调者支持 plan 模式时自动选择；不支持时会在审计中说明，不能据此承诺只读权限。协调结果必须为可校验的 JSON，格式或范围有问题就交回人工确认，不无限循环猜测。任务规则可在插件配置中调整。

授权等待、阻塞、未知结果、完成待确认都可从任务面板打开内部会话详情；保持在 Superagent 页面，不跳入普通终端区。确认完成不会自动合并或推送分支。取消、禁用、重载只停止该任务自己的连接，保留 Worktree 和日志；后台退出或连接中断后记录为中断，只有显式重试才从协调阶段创建新尝试。已在 Agent 内独立启动的外部任务仍需人工核对。

并行任务默认 2 个，可配置 1–4 个。任务列表显示最近 50 个摘要，未结束任务最多 200 个；审计和完整任务字段保存在插件 SQLite 中，可通过 `get` / `read` 分页读取。它是首版任务编排插件，并非 DeepSeek 原型全部业务功能的复刻。

## 自定义信息源插件

从零开发请先阅读 [Superagent 信息源开发指南](SUPERAGENT_SOURCE_DEVELOPMENT.md)。应用中可在插件中心 → Superagent → 配置 → 开发文档与工具打开同一指南，复制给 Agent 或导出含完整可运行示例的开发套件；下面是详细接口参考。

**不内置、不自动安装 GitHub 或飞书信息源。** Superagent 不感知特定渠道，只接收已注册插件提交的规范事件。开发套件中的 `superagent-source-local` 是可选本地模拟示例，不连接外部服务。

清单声明依赖 `superagent`（使用独立构建版本时改为对应插件 ID），然后注册信息源：

```js
exports.apply = ctx => {
  const source = ctx.berth.source({
    id: 'inbox', name: 'My inbox',
    // 可选：仅在用户明确确认回复时调用。必须按 key 做持久幂等。
    async reply({ threadId, text, idempotencyKey }, signal) {
      return { receipt: await sendOnce({ threadId, text, idempotencyKey, signal }) };
    }
  });
  ctx.berth.effect(() => {
    const stop = subscribe(async nativeEvent => {
      const receipt = await source.emit({
        id: nativeEvent.stableId,
        threadId: nativeEvent.threadId,
        actorId: nativeEvent.authenticatedUserId,
        title: nativeEvent.title,
        text: nativeEvent.body
      });
      // 收到接收或明确拒绝回执后才能提交来源游标。
      await acknowledge(nativeEvent, receipt);
    });
    return stop;
  });
};
```

此代码展示契约，`sendOnce` / `subscribe` / `acknowledge` 由插件实现；可直接运行的示例在 `examples/superagent-source-local`。

### 管道扩展字段

`ctx.berth.source()` 可声明 `pipelineConfigSchema`（字段类型与插件清单配置一致，另支持 `required`），并实现 `match(event, {pipelineId,pipelineName,config}, signal)`。宿主生成来源专属配置表单，在 `inputs[].config` 中按管道与来源分别保存、校验并补充默认值。`match` 返回 `false` 仅过滤此管道；异常保留失败回执，可用原事件 ID 重试。无 schema / match 的旧插件继续按原方式接收。

管道另提供独立 `filter:{includeKeywords,excludeKeywords,mode:'any'|'all',caseSensitive}`；关键词先于插件匹配执行，不需要插件在全局过滤消息。完整字段约束、执行顺序、热更新和重试边界见 [开发指南](SUPERAGENT_SOURCE_DEVELOPMENT.md#管道专属配置与关键词过滤)。

### 契约与生命周期

| 项目 | 约定 |
| --- | --- |
| 注册身份 | 完整来源 ID 为 `插件ID/来源ID`；来源 ID 为小写字母开头的字母、数字、点、连字符，最多 64 字 |
| 事件 | `id` / `actorId` 非空且最多 200 字，`threadId` 最多 500 字；`title` 1–100 字；`text` 1–16000 字；未知字段拒绝 |
| 身份 | 插件校验渠道签名、登录与真实用户身份；正文自称的身份不能当 `actorId` |
| 接收 | `emit` 返回 `{accepted, duplicate, ticketId?, ticketIds?, deliveries?, reason?}`；每项 delivery 含管道 ID、名称及任务 ID。部分失败会抛错并保留成功回执，原 ID 重试只补失败项；同来源同事件的订阅集合固定，不重复调度 |
| 未配置、已停用、临时错误 | 抛错表示尚未确认接收。插件持久保留事件，以相同 ID 重试，不先推进来源游标 |
| 准入 | 用户在 Superagent「信息源」中绑定项目与两个 ACP Agent；自动准入必须明确填写允许身份名单，否则待人工批准 |
| 信息源状态 | `source.health('ready'|'error', detail?)`，用于报告连接状态；不包含密码或令牌 |
| 回传 | 可选 `reply`，只发送用户审核的文字；`idempotencyKey` 跨显式重试保持不变，来源适配器负责持久去重 |
| 超时 | 回传默认 30 秒；传入 AbortSignal，插件必须取消自己持有的请求。已发送但回执丢失记为 unknown，不自动重发 |
| 清理 | 在 Cordis effect 中关闭监听、连接、文件句柄和计时器。禁用或卸载后旧 source handle 不再接受事件 |
| 持久化 | 来源连接参数、接收游标、幂等回执存在自身 `ctx.berth.dataDirectory`；不要存在全局临时变量里 |

`actorId` 白名单属于身份匹配，不是正文提示词。任务内容仍来自外部输入，协调者的权限取决于实际 Agent 配置。工作台的确定性校验不等于防止 Agent 一切越权操作。

自定义来源可以是 Webhook、轮询队列或本机事件，不要求修改工作台核心。上游重发、热更新、宿主重启、丢失发送回执等情况都应使用真实插件回归验证。开发期先安装本地模拟来源，再在信息源页面设置规则，验证接收、拒绝、去重和回传。

## 包体与 DeepSeek Harness 兼容边界

插件 ZIP 上限 256 MiB，展开总量 1 GiB，单文件 256 MiB，最多 50000 个条目，目录深度最多 32 层；检查元数据和实际解压字节数。采用分块解压落盘，不再一次性读入整个 ZIP。80 MiB 实际存储型 ZIP 已有回归测试。ZIP 根目录必须有 `agentberth.extension.json` 和已打包 `.cjs` 入口。

| 层次 | 是否可以直接复用 |
| --- | --- |
| Cordis 生命周期、effect、服务依赖思路 | 可以复用，版本固定为 4.0.0-rc.12 |
| 纯 Node 算法/协议代码 | 取决于实际依赖和许可证，打包后可复用 |
| Harness 清单、Agent/session/tool 服务、消息模型 | 不能直接通用，需要适配为 AgentBerth 清单与 `ctx.berth` API |
| Harness 前端扩展、桌面桥与权限 | 不能直接通用，需要适配视图消息桥和桌面入口 |
| GitHub/飞书信息源 | 不随 AgentBerth 附带；需要时自行开发来源插件 |

**不承诺 100% 兼容 DeepSeek Harness 插件。** 放宽 ZIP 大小解决容量问题，不改变宿主 API 的差异。缺少 AgentBerth 清单时会明确报告兼容性原因。

设计参考：[deepseek-ai/dsh-superagent-prototype](https://github.com/deepseek-ai/dsh-superagent-prototype)，保留其 MIT 声明于 `docs/third-party/dsh-superagent-MIT.txt`。本实现使用 AgentBerth 的 ACP 会话、Worktree、Cordis 生命周期和视图桥，不打包上游渠道代码。

## 真实 OpenCode 回归

CI 使用测试目录中固定版本 OpenCode 1.19.5 验证 initialize、创建会话、模型选择、plan 模式和相同原生 ID 恢复。测试只配置本机占位提供者，不提交 prompt、不调用模型、不登录、不安装 hook；XDG 配置、数据和缓存均隔离。测试用 CLI 不进入发行软件包。

OpenCode 的模式由标准 `configOptions` 提供，部分较早的 Agent 则返回 `modes`。工作台优先使用实际声明的配置项，旧模式接口仅在没有同名配置项时使用；Superagent 同时识别两种 plan 模式声明。没有可选值的配置项显示禁用状态。

已有本机 OpenCode 可手动复用同一回归（需先安装项目开发依赖）：

```powershell
$env:AGENTBERTH_OPENCODE_TEST_EXECUTABLE = 'C:\path\to\opencode.exe'
node scripts/test-opencode-acp.mjs
```

这组测试验证真实 CLI 的协议和会话管理，不等同于对所有模型提供者、真实任务或私有 Agent 的完整兼容承诺。


## 对话阅读、工具与桌宠

ACP 用户消息右侧显示，Agent 回复左侧显示。回复和 CLI 原生历史均支持 Markdown、表格、代码高亮、复制消息和复制代码；原生历史可搜索文本、收起会话列表，先显示最近 50 条，再按需加载。加载更早记录保留阅读位置，ACP 流式更新时可以回到最新消息。

同一 `toolCallId` 的异步、交错更新合并成一张卡片。卡片显示执行状态，可展开输入、结果、资源、文件增删行和终端输出；位置按钮打开项目预览。计划显示逐项进度，思考默认折叠，授权始终需要用户明确选择。Agent 声明的 slash commands 可在输入 `/` 时选择，不自动执行。

客户端终端预览显示保留输出的末尾 16 KiB，释放或停止后仍可查看；此显示限制不改变 Agent 自己通过 ACP 获取的命令结果。工具事件按已有历史保留策略有界存储，超限会明确说明，不承诺无界保存图片、日志和文件差异。外部链接需点击，远程图片不会自动加载。

ACP 和 Superagent 自动驱动桌宠，不需要修改 Agent 配置或安装 hook。ACP 显示执行、授权等待、完成和异常；Superagent 每个任务只显示一个条目，聚合协调者与执行者，右键可以切换并打开对应任务。不会把普通 Shell 或 SSH 加入桌宠，也不会因为长任务超过十分钟便把原生状态降为未知；后台断开则明确显示状态待确认。

## Superagent 的角色模型

创建任务及绑定信息源时，分别选择协调 Agent、协调模型、执行 Agent 和执行模型。点击「读取可用模型」从实际 ACP 配置项读取模型；保留默认选项即跟随 Agent 默认。模型 ID 保存在任务和来源规则中，继续任务时沿用。模型读取复用匹配的活跃会话；必要时创建一个空白原生会话，仅协商配置，不发送 prompt。未声明模型配置的 Agent 只能使用默认模型。

执行前，工作台会再次核验并设置该角色的模型。所选模型被上游移除或不可用时，任务会明确中断且不会发送任务 prompt，不静默换模型。协调者的 plan 模式与模型分别设置，不会为改变模型而修改用户全局 Agent 配置。

后台 API 53；当前架构的 API 44–52 后台可先保持连接，删除撤销、服务终端与原生 Web 视图需要更新后台。停止运行中的会话后可使用「更新空闲后台」。Schema 6–8 的项目、会话和任务数据保留，升级时自动补齐服务字段并创建删除撤销快照表，最终为 schema 9；更早架构继续遵循原来的数据隔离要求。


## 在哪里回答 Superagent

任务提出的问题统一在 **Superagent → 对应任务 → 底部输入框** 中填写，点击 **发送并继续**。协调阶段继续原协调会话，执行阶段继续原执行会话；保留项目、Worktree、模型和本机对话记录。Agent 支持原生恢复时沿用原生会话，不支持时会明确创建新原生绑定并携带本次回答和上一轮摘要。继续采用新的请求 ID，同一次提交重试不会重复发送。

- **等待你的回答**：在任务页回答上方问题后发送。
- **等待会话授权**：点击「打开协调会话」或「打开执行会话」选择授权，处理后自动继续。
- **等待验收**：查看结果后选择「确认完成」，有修改意见则输入并「发送并继续」。
- **任务中断**：先核对实际执行结果；「重新协调 / 显式重试」经确认后从协调阶段创建新尝试，不自动重跑。

关联 ACP 会话用于查看过程与授权，底部提供「返回任务并回答」，不再提供会脱离任务状态的独立发送入口。桌宠打开同一任务并区分上述等待原因。协调报告前后的普通说明、Markdown 代码围栏可以解析；没有有效 JSON 决策时仍明确等待人工处理，不猜测执行方案。

工具卡片按读取、修改、命令等类型显示图标和状态。命令、参数、结果可单独复制，命令和 JSON 支持语法高亮；文件改动显示增删统计、双行号与复制修改后内容。协议原文保留在折叠详情中。


## 独立任务工作区、运行中输入与提问

Superagent 的协调、执行会话带持久归属，**不出现在普通会话树或快速切换列表**。任务页的「打开协调会话 / 打开执行会话」在本特性内查看 ACP 过程和处理授权，点击「返回任务」回到同一页面。停用、重载插件及重新尝试都不解除归属，避免历史内部会话重新混入普通列表。不按会话名称猜测归属，普通用户创建的同名会话保持普通会话。

任务信息可展开查看内部会话历史，包括前几次尝试的会话；支持查看、分页，以及显式删除已停止且不再被活跃任务使用的记录。不会按空闲时长自动回收长任务。

任务运行中输入要求后，默认 **排队发送**（Enter；Shift+Enter 换行），本轮结束后按顺序继续同一阶段。待发送消息在输入框上方显示，可撤回。最多 20 条待处理指令，按请求 ID 去重；单条最多 12000 字，不会并发调用一个 ACP 会话。

**停止并插话** 会请求取消当前轮次，等待 Agent 确认结束后，优先发送该条要求；原有排队消息保留。停止不回滚已完成的外部操作。Agent 不确认取消时保持等待，不伪装插话已生效。权限请求仍须人工选择，不把补充消息当成授权。

连接中断、宿主退出或插件重载后保留排队消息；结果不明确的发送标为待确认，不自动重发或重跑旧请求。用户核对执行记录后显式重新协调。取消任务撤回尚未发送的消息。

协调报告的 `ask` 显示为问题卡片，支持单选、多选与自定义回答。可以返回原有 `question` 字符串，也可声明：

```json
{"action":"ask","reason":"确认范围后继续","questions":[{"header":"验收方式","question":"使用哪种验收方式？","multiple":false,"options":[{"label":"运行测试","description":"执行项目的回归测试"},{"label":"人工检查","description":"核对关键界面"}]}]}
```

回答从同一队列送入协调者。最多显示 8 个问题、每题 12 个选项；过长内容明确提示打开协调详情核对，不把原始 JSON 当作交互卡片。此机制用于 Superagent 决策报告；不会为上游 Agent 伪造私有问答协议。

页面采用任务列表、对话进展、折叠元数据与底部固定输入框。实时文本是有界预览，完整的已保留 ACP 记录在内部会话详情中查看。已接收的任务消息与结果保存在本机，阅读支持分段加载和展开全文。深浅色同步覆盖原生选择控件和滚动条。

### 任务看板与执行可见性

Superagent 默认打开任务看板，按「待批准 / 进行中 / 需要处理 / 已结束」分组；卡片显示具体等待原因、项目、当前 Agent、摘要与最近活动。左侧搜索、状态筛选和分页同时作用于看板和列表；列数量为当前页，顶部显示总数，历史任务不会因分页被宣称全部展示。状态来自实际任务和 ACP 事件，不估算完成百分比。

任务详情上方显示当前执行者、阶段、等待原因、操作入口和最近事件时间。等待工具授权时直接点击「处理授权」进入对应 ACP 会话；回答、排队和插话仍在任务输入框。对话下方默认展开最近工具/轮次摘要，含状态与时间戳；更早记录或完整参数/输出通过「打开完整执行记录」查看，不把全部日志灌进任务页。状态与决策另外组成时间线。

更多操作菜单在点击操作、切换任务、切换页面、点击空白处或按 Escape 时关闭。删除确认绑定发起时的任务，取消不会留下菜单；异步删除完成也不会把用户后来打开的另一任务清空。

Superagent 任务对话、ACP 对话和 CLI 历史统一支持滚动到顶部自动加载更早消息，无需点击分页按钮。按页追加、防止重复加载，并以可见消息为锚点保持阅读位置；切换任务/会话会丢弃旧加载结果，阅读旧消息时新输出不会强制跳到底部。

### 批量任务管理

看板卡片和任务列表均可勾选任务，或选择当前页（最多 50 项）。工具栏提供批量批准、拒绝、删除；批准/拒绝只适用于尚未批准且未结束的请求，普通任务和已结束项会明确跳过。操作前预览符合条件的数量与标题；删除有运行连接的任务需要明确确认停止，执行时再次检查，后来才启动的任务不会被未经确认地停止。

每项独立返回成功、跳过或失败，一个失败不会遮住其余结果。成功/跳过项取消选中，失败项保留供核对；不会自动重试。批准、拒绝、删除都不会自动向来源发消息；删除保留工作区文件与来源去重记录。更换搜索、筛选或页码会清除当前页选择，避免在看不到的任务上误操作。

## 非 Git 管道工作区

管道卡片的“工作区”提供扫描和建立隔离副本。扫描前设置排除规则和容量，确认文件数、大小和链接跳过项，再建立副本。没有副本时任务不在原目录启动，建立后显式重试。Git 不可用时也可人工选择副本。协调和执行使用同一管道目录，任务串行。

完成或取消任务后查看新增、修改、删除及冲突，预览基线和副本，再选择文件应用到原项目。应用前重新检查，变化项不覆盖。每次最多 32 个选择项，列表按 50 项分页；每侧文本预览最多 8 KiB，应用使用完整文件。可导出修改到独立目录，或重新扫描并确认重建。管道删除后，在“保留的工作区”查看、导出或清理副本。

协议 isolatedWorkspace 提供 scan/create/reset/changes/preview/apply/export/delete/status/job/cancel/list。长操作返回后台 job，读取同一 job 不重放操作；取消保留已经成功应用的项。副本绑定校验覆盖会话创建、启动、历史目录和文件预览。实现边界见 [非 Git 工作区设计](design/non-git-pipeline-workspaces.md)。


### ACP 启动与会话恢复

自定义 ACP 接入的“高级配置”可设置启动等待时间（5–600 秒，默认 180 秒），涵盖 npx
首次下载与协议初始化；超时错误包含末尾启动日志，不自动重复执行。启动参数仍需使用
JSON 数组，普通 TUI 或 Web 服务不能作为 ACP 启动程序。

AgentBerth 根据 Agent 声明协商 `session/resume` 或 `session/load`，本地记录保留；
两者均未声明时才建立新会话，且不会重放旧消息。
