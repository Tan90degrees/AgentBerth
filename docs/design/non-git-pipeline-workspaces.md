# 非 Git 项目的管道隔离工作区

状态：方案已确认，已实现于 PR #19。后台 API 50，schema 7 保留。

## 使用

Superagent → 来源管道 → 管道卡片的“工作区”。Git 项目继续使用固定 Git Worktree；非 Git 项目使用持久隔离副本。扫描前可调整排除规则和容量上限，扫描展示文件数、体积、工作目录与基线预计占用、剩余空间及链接/特殊文件。确认范围后建立副本；链接与特殊文件需要明确选择跳过。支持进度和取消，不自动安装依赖。

非 Git 任务不会直接在原项目中启动。没有副本时提示先扫描并建立，再显式重试任务；协调和执行随后均绑定到该管道的副本。同管道任务串行，不同管道互不影响。已有副本的项目绑定不能更换。

## 数据与恢复

副本保存在应用数据目录的 isolated-workspaces 下，包含工作目录、基线内容和文件哈希清单。不在原项目创建 .git，不用硬链接共享可修改文件。复制先写暂存目录，核对源文件前后哈希和复制范围，再以目录重命名发布；源文件发生变化时明确失败，原有副本保留。不宣称跨进程原子快照。

每管道默认容量上限 8 GiB，可调整至 128 GiB；文件和目录分别最多 50000 个。容量检查和有界缓冲控制复制开销，基线也占用磁盘空间。取消或失败会清理未发布的暂存目录。重建过程中退出，重启时恢复尚未发布替换前的旧副本；完成发布后的旧备份与未发布暂存目录才会清理。

## 差异与应用

面板分页显示新增、修改、删除、阻塞项及原项目冲突。预览对照基线和副本，每侧文本最多显示前 8 KiB；二进制文件只显示状态，应用仍使用完整文件。可选择最多 32 个文件明确应用，删除也列入确认清单。应用前重新核对基线、当前副本和原文件，变化项不覆盖；每项独立报告成功或冲突，部分成功不会默默回滚，也不自动重试。成功项更新基线，未应用项保留。

应用与原目录的外部写入没有跨进程事务；哈希检查用于发现变化，不能对不配合的外部进程提供文件锁。路径中的链接会阻止对应文件应用，不沿链接写入项目外。隔离副本不是 Agent 进程的安全沙箱。

“导出修改”生成独立目录，包含新增/修改文件、changes.json 删除列表及基线哈希，不自动修改原项目。“重新建立副本”需要重新扫描并确认替换未应用修改，建议先导出。

## 清理

任务删除与管道删除均保留副本。来源管道 → 保留的工作区列出无管道绑定的副本，可查看差异、导出，再明确清理。清理仅删除副本，不删除原项目。运行中、等待授权、等待回答或待验收的管道需先完成或取消任务，才能应用、重建或清理工作区。
