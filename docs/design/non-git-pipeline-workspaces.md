# 非 Git 项目的管道隔离方案（待审核）

状态：提案，未实现。当前管道要求 Git 仓库；非 Git 项目不会回退到共享目录。

## 推荐：每管道一份隔离副本

用户选择项目后，为每条管道在应用工作区目录建立持久副本。协调与执行 Agent 均在副本运行，同管道任务串行，不同管道互不影响。不在原项目中创建 `.git`，不自动覆盖原目录。

创建前展示复制范围、预计文件数与大小。默认排除 `.git`、`node_modules`、缓存和构建产物；用户可以修改排除规则，并为没有被复制的依赖选择自己的安装命令，应用不擅自安装。保留隐藏的项目配置文件；不把排除规则当作秘密文件过滤保证。

文件复制在临时目录完成，通过原子重命名发布工作区；支持取消和磁盘不足错误。对复制时变化的文件重试或报告失败，不宣称取得原子快照。符号链接不跟随到项目外：创建前报告并要求选择跳过或取消；不会通过硬链接共享可修改文件。大文件、权限和平台不支持的文件类型明确显示处理结果。

## 查看和应用结果

建立副本时保存基线清单及文件哈希，提供新增、修改、删除的对比。用户可以导出结果，或选择文件、预览差异后明确应用到原项目；没有自动双向同步。应用时再次检查原文件与基线：若原项目已修改，同一文件进入冲突处理，不静默覆盖。删除文件也需要包含在用户确认的清单内。

任务完成后保留管道副本，下一项任务接着使用。用户显式“重新建立副本”才从原项目获取新的基线；若副本有未应用修改，先提供导出和确认。任务删除不清理副本；删除管道后，工作区单独列入可清理列表，显示大小、位置与未应用修改，用户明确清理后才删除。

## 命名与现有 Git 行为

界面统一称为“隔离工作区”：Git 项目标为 Git Worktree，非 Git 项目标为隔离副本。两者都绑定管道，不能切换到另一个项目后复用旧工作区。
